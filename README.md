# BPS Relay

持久 WSS 通道上的 HTTP/SSE 中继，配合 BPS for Magpie 的可选客户端使用。
本机连接中继，服务器向原 BPS HTTPS 接口发送请求，并把状态、相关响应头和正文流传回。
它不提供模型、账号池或 MCP 工具，也不改写模型、思考强度、工具参数和 SSE 内容。

## 边界

- 服务端不设置并发请求、连接或账号数量上限；本地 Magpie 管理自身并发。
- 请求编号在每条连接内隔离，不同电脑可以用同一个或不同账号。取消只作用于对应请求。
- 不设置整条请求/响应的总字节上限，不设置推理总时长截止。32 KiB 分片和 256 KiB
  信用窗口只控制在途数据，不是消息总量限制。实际容量仍取决于机器、磁盘、内存和上游。
- 大请求先写入权限为 0600 的临时文件，接收完整后发送上游，完成/取消后删除；授权头
  仅在内存中转发。部署使用 PrivateTmp，异常退出后的临时目录由 systemd 管理。
- 客户端、服务器心跳保活；失联检测为 180 秒，TCP/TLS 建连最多 60 秒。
  Nginx 的读写空闲期限建议至少 600 秒。正常心跳和持续生成不会触发总时长截止。
- 连接断开会取消该连接内的请求。客户端可为后续新请求重新建通道，已提交的请求不会自动重放。
- 固定目标白名单只允许 BPS 推理/附件/模型访问、账号额度读取和 OAuth 换票/刷新。
  不接受任意目标、重定向、cookie、代理认证头或幂等重试头。上游错误状态按原样返回。
- HTTP 活跃连接不设上限；128/64 的池参数只限制保留的空闲连接，不限制处理中的请求。
- 心跳不消除 TCP 丢包、重传或中间网络故障，也不能绕过上游权限和使用策略拒绝。

客户端应当只使用自己信任的中继：TLS 在服务器终止，中继能够接触请求内容和授权信息。
本服务不记录这些信息，不管理或保存账号，不自动刷新凭据；OAuth 仍由客户端发起和保存。

## 构建与运行

需要 Go 1.27.4+：

```sh
go test ./...
go vet ./...
go build -trimpath -o bps-relay ./cmd/bps-relay
export BPS_RELAY_TOKEN='replace-with-a-random-base64url-token-at-least-32-characters'
export BPS_RELAY_LISTEN='127.0.0.1:19361'
./bps-relay
```

默认只监听 loopback，前面使用 Nginx 提供有效证书的 TLS。不要把未加密的监听端口直接公开。
访问密钥放在权限受限的环境文件中，不要写进命令行、URL 查询或源码。
GET `/healthz` 返回进程状态；WSS `/relay` 在握手时要求 `Authorization: Bearer ...`。
浏览器 Origin 被拒绝，因为这是原生插件通道。

部署示例见 [deploy](deploy)。域名、证书和密钥均由部署者提供，没有内置服务器地址。
客户端中继默认关闭，用户须手动填写 WSS 地址和密钥后启用。关闭后走原网络路径。
客户端连接中继采用直连，不隐式继承 Magpie 的 HTTP 代理；运行系统自身的 VPN/TUN 仍可能介入。

本仓库不更改 Magpie 或 BPS 插件既有的整包/图片限制。当前 BPS 插件的原有请求体上限为
64 MiB；若客户端在进入中继前拒绝大请求，中继本身不限总大小不能解除该客户端上限。

## 协议与验证

协议见 [PROTOCOL.md](PROTOCOL.md)。测试覆盖原始正文、错误状态、身份隔离、12 个客户端并发、
取消、信用窗口、未完整上传不发送上游、认证和目标白名单。客户端联调验证了 65 MiB 请求、
130 MiB 响应、同通道复用与单请求取消。另已验证远端 TLS/WSS 和真实只读模型访问。
没有以这些测试宣称所有模型推理或所有网络情况下都能恢复。
